# Claude Code 指示書(第5弾): 見積ファイルを取り込んで、案件と見積を登録する

## 0. 進め方

- 共通のルールは第1弾の「2. 守ってほしいルール」と同じ
  - 別ブランチ(`feature/quote-import`)/ 既存機能を壊さない / **DBの変更は自分で実行せずSQLを出す** / 金額計算はプログラム / 小さく区切って日本語で報告 / 迷う点は聞く
- 私は**Claude Proプラン**。**ステップごとに区切って**、終わるたびにコミット・報告して止まる
- **ステップ0(調査)の結果を報告するまで、コードは書かない**
- **このリポジトリは公開(パブリック)**。秘密のキー・実際の物件名・個人名を、コードやドキュメント、テストデータに書かない(架空のものを使う)
- **mainにマージする前に、必ず私に確認する**

## 1. ゴール

作成済みの**見積ファイル(Excel)を取り込む**と、**案件と見積が自動で登録される**ようにする。
いまは、見積はアプリの中で単価表から作る方法しかなく、**既存の見積ファイルを入れる場所がない**。

- 見積ファイルをアップロード → 内容を**読み取り** → **確認画面**で直す → **登録**
- 登録されるもの: **案件**(新規、または既存の案件に追加)と、その中の**見積(明細つき)**
- **元のファイルは、案件に紐づけて保管**する(あとから開ける)
- **今回の読み取りは、AIを使わない**(Excelの形が決まっているため。金額の正確さのため、プログラムで読む)

## 2. 今回やらないこと

- PDFの読み取り(AIが必要。別の回でやる)
- 現調ノートからの下書き(第3弾)、見積書の出力、元請向けの見積変換
- 「ESTファイル」(見積ソフトの元データ)の読み取り
- 既存の列・データの変更、ログイン・権限の仕組み

## 3. 読み取るファイルの形(Conclu出力の見積書。拡張子は `.xls`)

3つのシート: **表紙 / 内訳明細 / 概要メモ**。読み取りに使うのは「表紙」と「内訳明細」。
(下のセル位置は、サンプル2件で確認済み。**ステップ0で、Codeが実際のファイルで確かめ直す**)

### 表紙
| 項目 | セル | 例 |
|---|---|---|
| 見積日 | AP3 | 2026年 10月 3日 |
| 御見積金額(税込) | W10 | 425,821 |
| 見積代金(税抜) | AG13 | 387,110 |
| 消費税 | AG14 | 38,711 |
| 工事名称 | I19 | ○○マンション305給水管更新工事 |
| 工事場所 | I21 | (空のことが多い) |
| 着工日 / 完工日 | L23 / L24 | (空のことが多い) |
| 宛先(様) | E6 | (空のことが多い。空だと `0` と入っている) |

### 内訳明細
- **33行ごとに1ページ**。各ページの見出し行(**C列が「No.」**)から、列は次のとおり
  - C: No. / D: 名称 / E: 材質・寸法 / F: 数量 / G: 単位 / H: 単価 / I: 金額 / J: 備考
- ページの構成(見出し行が6、39、72、…の場合):
  - **1ページ目 = 総括**(「◯◯工事費 一式」「一般管理費 一式」と、総合計)。**明細としては取り込まない**(二重計上になる)
  - **2ページ目以降 = 各グループの内訳**。ここを明細として取り込む
  - 各ページの末尾に、**「合計」の行**と、**グループ名の行**(例: `給水管更新工事費 0001 - ( 0002 )`)がある。グループ名(`0001 - (…)` の前の部分)を、明細のグループ名に使う
- 注意すべき行
  - **名称(D)が空で、材質・寸法(E)に「同継手材」などと入っている行**がある。この場合、材質・寸法の文字を名称として使う
  - **数量も金額もない行**(見出しだけの行)は、読み飛ばす
  - 「合計」「総合計」の行は、**検算に使う**(読み取った明細の合計と一致するか確認する)
  - **備考(J)に「定価29700円」のような文字**が入ることがある。そのまま備考として保存する
- 1つのファイルに、グループ(ページ)が3つ以上ある場合もある。見出し行を探して、すべて読む

## 4. 金額の扱い(**重要**)

- **案件の売上・粗利は、「載せる前」の金額で計算する**(確定)
- 見積ファイルの金額は、**7.5%を載せた後(元請に出す金額)**のものが多い。載せ後の金額は、各明細の単価 ÷ 0.925 で作られている
- そのため、取り込みの確認画面に、**次の選択を必須で入れる**(選ばないと登録できない)
  - ○ このファイルの金額は**載せる前**(そのまま登録する)
  - ○ このファイルの金額は**載せた後**(7.5%載せ後)→ 単価を **× 0.925** して、載せる前に戻す
- 「載せた後」を選んだ場合
  - 各明細の**単価に 0.925 を掛けて、円未満を四捨五入**し、金額 = 数量 × 単価 で計算し直す
  - **元のファイルの合計との差額**(円未満の処理による差)を、確認画面に表示する
- 税: 見積の金額は**税抜**で保存する(消費税は別)

## 5. 単価表への当てはめ(原価を付けるため)

- 取り込んだ明細に、**単価表(price_items)の項目を当てはめて、原価を付ける**
  - 名称と材質・寸法の文字が**単価表と一致**すれば、そのまま当てはめる
  - 一致しない行は、**文字の類似度で候補を出して**、人が選ぶ。**AIは使わない**
  - **別名辞書(price_item_aliases)**を使い、人が選んだ当てはめは辞書に保存する(第3弾と共通の処理にしたい。重複して作らない)
- **当てはまらない行は、「原価未入力」**にする(粗利は「暫定」表示)
  - 特に、**「同継手材 一式」のようにまとめられた行**は、単価表の1項目に対応しないため、原価未入力になる想定
- **売価(単価・金額)は、ファイルの値**をそのまま使う(4節の変換後)。**単価表の売価で上書きしない**
- **原価は、いまの単価表の原価を、取り込み時点でコピーして保存する**(既存の見積作成と同じ。`quote_item_costs`)
  - 過去の見積を取り込んだ場合、**粗利は「いまの原価」での目安**になる。確認画面に、そのことを一言書く

## 6. 案件への登録

- 確認画面で、次を決める
  - **案件**: 新規作成 / 既存の案件に追加。**案件名が同じ・似ている既存案件があれば、候補として出す**(二重登録を防ぐ)
  - 新規作成の場合: 案件名(初期値 = 工事名称)、元請(`clientId`。選択)、元請側の担当者(`salesRepId`。選択)、現場担当(`inCharge`)
  - 見積の状態: draft / submitted / won / lost(初期値 `submitted`)
- **案件の売上(amount)・粗利(grossProfit)は、登録時には入れない**。反映は、既存の**「採用にする」**(確認ダイアログつき)で行う
- **変換版は、元の見積IDを参照している見積(`source_quote_id`)**。取り込んだ見積は、変換版ではない
- 取り込み後、**見積の編集画面で、明細を直せる**(既存の画面)

## 7. ファイルの保管

- 元のファイルは、**Supabase Storage**に保存して、案件・見積に紐づける
  - 保存先のバケットは、**非公開**にする。公開URLを作らない(署名付きURLで開く)
  - 保存名は、安全な名前(ID+拡張子)にして、元の名前は別に記録する
- DBの変更が必要な場合(例: `quote_files` テーブル)は、**SQLを提案する**(実行はオーナーが行う)。バケットの作成手順も示す
- サイズの上限(例: 10MB)を入れる

## 8. 画面

- 案件の詳細 → 見積のセクションに、**「見積ファイルから登録」**ボタン(案件一覧にも置く)
- ファイルの選択(`.xls` / `.xlsx`、複数ファイル可)
- **確認画面**(ファイルごと): 表紙の情報、明細の一覧と当てはめ結果、検算、載せ前/載せ後の選択、案件の選択、行の編集・削除
- **登録**を押すと、案件(必要なら)・見積・明細・原価のコピー・元ファイルが保存される
- **登録は、途中で失敗した場合に中途半端なデータが残らない**ようにする

## 9. ステップ

- ステップ0: 調査(コードは書かない)
- ステップ1: 読み取りだけ(保存しない)
- ステップ2: 登録
- ステップ3: ファイルの保管

## 10. 確認方法

- [ ] サンプルのファイルを読んで、工事名称・金額・明細が正しく表示される
- [ ] 読み取った明細の合計が、ファイルの合計と一致する(一致しない時は警告が出る)
- [ ] 「載せた後」を選ぶと、単価が × 0.925 になり、金額が計算し直される
- [ ] 載せる前/載せた後を選ばないと、登録できない
- [ ] 同じ名前の既存案件がある時、候補として出る
- [ ] 登録した見積が、案件の見積一覧に出て、既存の編集画面で直せる
- [ ] 原価が、単価表から付く。当てはまらない行は、原価未入力・粗利暫定になる
- [ ] 案件の売上・粗利が、**登録しただけでは変わらない**
- [ ] 元のファイルが、案件から開ける。公開URLになっていない
- [ ] 既存の画面・ダッシュボード・見積作成が、今まで通り動く
- テストは**【テスト】の案件**で行い、終わったら削除用SQLを出す
